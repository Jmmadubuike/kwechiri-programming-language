# ADR-027: Kwechiri 1.0 compatibility and diagnostics

## Context

Kwechiri 1.0 needs a stable language surface, predictable package versions,
and diagnostics that editors and learners can rely on. The owner approved the
Milestone 14 decision register on 2026-10-30.

## Decision

### Language surface

The current implemented surface in the
[1.0 language surface inventory](../roadmap/KWECHIRI-1.0-SURFACE-INVENTORY.md)
is the frozen language surface. The five `kwechiri:eriri` functions
remain the complete Standard Library for 1.0 unless another batch is explicitly
approved.

No deferred feature becomes part of 1.0 merely because it appears in roadmap or
historical documentation.

### Versioning

Kwechiri follows semantic versioning:

- a major release may change or remove syntax, semantics, public APIs, CLI
  contracts, or diagnostic codes;
- a minor release may add compatible syntax, APIs, diagnostic codes, or
  capabilities and may improve messages;
- a patch release fixes defects without intentionally changing the language
  contract.

The compiler package version identifies the language and compiler contract.
Pre-release versions use an approved release-candidate suffix. The owner
approves the version and publication target independently of implementation
completion.

### Stable public contracts

Within a major version, Kwechiri preserves:

- `.kwe` as the Kwechiri source extension;
- implemented keywords, operators, and semantics frozen for 1.0;
- relative filesystem and `kwechiri:` module identity and resolution;
- the `kwechiri` command names and documented options;
- stdout/stderr separation and CLI exit codes;
- stable diagnostic codes and their conditions;
- existing Standard Library module and export names;
- the documented Kwechiri runtime behaviour and output vocabulary.

### Internal contracts

Generated JavaScript is a compiler output artifact, not a separately supported
source language. Its internal shape may change without a language-major release
provided the CLI contract and execution behaviour remain compatible. Compiled
CLI artifacts may continue to require the Kwechiri installation that generated
them.

Internal TypeScript modules, AST node shapes, resolved nodes, generated binding
names, and source maps are not public APIs unless a document explicitly says
otherwise.

### Deprecation

A deprecated public feature remains available for at least one minor release
after deprecation is documented, unless it creates a security or correctness
hazard. Removal occurs only in a major release. Migration guidance and release
notes must name the replacement when one exists.

### Diagnostics

Public codes use `KWE-<CATEGORY>-<NNN>` and are listed in the
[stable diagnostic catalog](../language-spec/error-catalog.md). Codes precede
messages in located and CLI output.

Within a major version, an existing code retains its condition and stage.
Messages may improve without changing the code. Dynamic names, types, and paths
may vary within the same condition. Removing or redefining a code is a major
change.

Compile-time and runtime diagnostics retain available filename, line, column,
offset, category, and source context. Line, column, and offset use UTF-16 code
units. Expected failures must not expose uncontrolled host stack traces.

Messages remain Igbo-first with an English parenthetical translation where
available. Improving bilingual coverage does not change a diagnostic code.

### Source encoding

Source files must be valid UTF-8. Invalid byte sequences are rejected as
`KWE-MOD-015` instead of being silently replaced.

## Consequences

The diagnostic catalog becomes an observable compatibility surface and must be
updated with every new public code. Editors can expose stable codes. Future
language and CLI changes must be classified against this policy, and release
notes must identify compatibility changes.

This ADR does not approve npm publication, a final version, supported-platform
claims, or a release. Those remain separate owner-controlled gates.
